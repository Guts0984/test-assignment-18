# Bugs found by tests

| # | Bug | Found by | Fix |
|---|---|---|---|
| 1 | With Redis unreachable, closing the job publisher waited for a connection for ever, so an api copy could not shut down. | `apps/api/test/adv/limiter.adv.spec.ts` (Redis down) | The publisher drops the socket without closing queues when Redis is not ready (`packages/queue/src/publisher.ts`). |
| 2 | Under load, requests failed with 500 because the connection pools of two api copies could exceed the Postgres connection limit. | `apps/api/test/cohorts.it.spec.ts`, webhook suite | `max_connections` raised in compose; pools bounded in tests. |
| 3 | Two different response schemas used the same DTO class name (`StudentPageDto`, `SubmissionDto`), so the OpenAPI document, and the generated client, described the manager's roster with the mentor's shape. | TypeScript type check of the web app against the generated client | Names made unique; `apps/api/src/openapi-names.spec.ts` fails on any reuse. |
| 4 | The worker's `ioredis` was only a development dependency, so the pruned production image crashed on start. | Compose start of the pruned images | Moved to runtime dependencies; `scripts/check-dependencies.mjs` runs in lint. |
| 5 | Seeded ids were `md5(...)::uuid`, which are not well-formed UUIDs. The response schemas rejected every seeded row, so on a fresh `docker compose up` the catalog and every login answered 500. | Smoke test through nginx on the seeded stack; reproduced by `apps/api/test/seeded.it.spec.ts` | Seed ids are version 4 UUIDs (`packages/db/seed/ids.ts`); the seed test checks every table. |
| 6 | The compose network had no fixed subnet. On a host whose usual Docker ranges were taken, it received `192.168.0.0/20` and the bridge claimed `192.168.0.1`, the home router's address, cutting the host off from Wi-Fi. | Developer machine lost its connection while the stack was up | The subnet is pinned (`COMPOSE_SUBNET`, default `10.213.47.0/24`), and only that range is trusted as a proxy. |
| 7 | On the full data set the manager's student search took up to 4.6 s (budget 300 ms) and the twelve-month report 1.9 s (budget 1 s). | `tests/perf/budgets.x.spec.ts` | A trigger-maintained `school_students` search table, covering indexes for the report, planner settings for solid-state storage (migration `0004`). |
| 8 | No deadline reminder was sent for the last week of homework: the cohort completes when the last lesson ends, and the reminder only went to students still `paid`. | `apps/worker/test/adv/queues.adv.spec.ts` | Reminders go to `paid` and `completed` students (`packages/db/src/repo/reminder.ts`). |
| 9 | On the staff page, buttons for a mentor with unfinished cohorts seemed dead: the server refused, and the reason appeared above a long table, out of view. In the seed this is every mentor. | Manual use of the seeded stack | The list reports each mentor's unfinished cohorts; blocked buttons are disabled with the reason, and errors show in their row. `apps/web/e2e/staff.static.e2e.ts`. |
| 10 | A changed `COMPOSE_SUBNET` left the trusted proxy range at the default, so every client was counted as nginx and one attacker could lock everyone out of sign-in. | `compose-config.it.spec.ts` | Compose derives `TRUSTED_PROXY_CIDRS` from `COMPOSE_SUBNET`. |
| 11 | A student past the third lesson (refund 0 %) could move to a later cohort and cancel for up to 100 %. | `transfer-refund.adv.spec.ts` | Students transfer only before their cohort starts; a transfer carries the refund percentage as a cap (migration `0005`). |
| 12 | A free cohort could never be booked: the hold waited for a payment of zero and expired. | `free-cohort.it.spec.ts` | A zero price enrolls at once, from a booking or an offer. |
| 13 | Work claimed by a mentor who was then disabled stayed `in_review` for ever. | `mentor-claim.race.adv.spec.ts` | Leaving mentoring releases held work; a claim re-checks the account under its lock. |
| 14 | `/login?next=%2F%09%2Fexample.com` redirected to another site. | `roles.spec.ts` | Control characters and backslashes are refused and the target is resolved before use. |
| 15 | While Postgres was down every route, including health, answered 500. | `database-outage.it.spec.ts` | Connection failures answer 503 `SERVICE_UNAVAILABLE`. |
| 16 | An access token kept working for up to 15 minutes after logout or refresh-token reuse. | `auth.adv.spec.ts` | Tokens name their session, which is checked on every request. |
| 17 | An open socket kept receiving staff updates after logout, disabling or a mentor change. | `realtime.adv.spec.ts` | Ending a session or account closes its sockets on every copy; a replaced mentor leaves the room. |
| 18 | nginx answered some bad requests with HTML. | `edge.x.spec.ts` | nginx errors use the shared JSON shape. |
| 19 | Resubmitting homework without choosing the file again deleted it. | `homework.it.spec.ts` | The file stays unless replaced or explicitly removed, and the form says so. |
| 20 | Stopping one api copy could lose a request with 502. A stopping copy also dropped connections the proxy had just used, and in-flight answers did not close theirs. | `edge.x.spec.ts`, `shutdown.it.spec.ts` | A leaving copy closes only its listening socket, answers what still arrives on open connections with `Connection: close`, and exits after a quiet second. It keeps idle connections longer than the proxy, and the proxy gives up on a failed connect quickly. |
| 21 | Test runs failed at random: closing right after starting left rejected Redis commands. | `shutdown.it.spec.ts` | Connections settle before closing, and unobserved adapter commands are logged. |
| 22 | The CSRF test assumed port 8080. | `csrf.adv.spec.ts` | It uses the configured origin. |
| 23 | Homework sent as anything but a multipart form (JSON, plain text, empty) answered 200 and emptied the answer text. | `homework.it.spec.ts` | The upload route refuses every other body with 415. |
| 24 | After signing out, open tabs never got live updates again: the server closed their socket and the web client did not reconnect. | `live.static.e2e.ts`, `auth.adv.spec.ts` | The client reconnects with growing delays, and a refused refresh clears the cookies so it returns as a visitor. |
