# Тестовое задание: онлайн-школа с потоками курсов

Онлайн-школа продаёт курсы потоками: у потока есть дата старта, расписание живых занятий, ограниченное число мест и цена. Студенты записываются и оплачивают через платёжную систему, делают домашние задания и получают сертификат. Менторы проверяют домашки. Менеджер школы ведёт курсы, потоки и расписание, решает вопросы с возвратами и переводами между потоками.

Если что-то неоднозначно, решите сами и запишите решение в README. История коммитов — по этапам работы, CI на каждый коммит.

---

## Стек

| Часть | Что использовать |
| --- | --- |
| База | PostgreSQL 16 + Prisma; сырой SQL там, где нужны блокировки, ограничения и отчёты. **Источник правды — Postgres** |
| Redis 7 | **BullMQ**: истечение брони места, предложения из листа ожидания, приём уведомлений от платёжной системы, возвраты, напоминания о занятиях и дедлайнах, сертификаты, письма. **Адаптер Socket.IO** между копиями `api`. При потере данных Redis ничего не теряется |
| `apps/api` | Node.js, NestJS: REST + OpenAPI (`@nestjs/swagger`), **Socket.IO** (`@nestjs/websockets`). В `docker compose` работают **две копии** за nginx |
| `apps/worker` | Отдельный процесс NestJS с обработчиками BullMQ. Можно запустить несколько копий |
| `apps/web` | Next.js 15 (App Router), React 19. Клиент API **генерируется из OpenAPI**; TanStack Query, React Hook Form, Tailwind |
| `packages/shared` | Общие для `api`, `worker` и `web`: Zod-схемы ввода, расписание занятий в часовом поясе потока, дедлайны, сумма возврата, условие сертификата, переходы статусов |
| Тесты | Vitest; интеграционные — на настоящих Postgres и Redis; e2e — Playwright |

## Сценарии

### Студент

1. Ищет курс в каталоге по названию, направлению, дате старта и цене. Видит потоки с числом свободных мест.
2. Записывается на поток: место **держится за ним 15 минут**, пока он оплачивает (на экране обратный отсчёт). Может применить промокод.
3. Если мест нет, встаёт в лист ожидания. Когда место освобождается, получает письмо с предложением: у него 24 часа, чтобы оплатить.
4. В личном кабинете видит расписание занятий в своём часовом поясе, домашние задания и дедлайны, оценки ментора и прогресс.
5. Сдаёт домашку (текст и файл), может пересдать до дедлайна. Видит комментарий ментора.
6. Просит перевод в другой поток того же курса или отменяет участие. Перед отменой видит, сколько денег вернётся.
7. После окончания потока скачивает сертификат, если выполнил условие.

### Ментор

1. Видит очередь домашек на проверку: сначала самые старые. Одновременно на проверке у ментора не больше 5 работ.
2. Принимает работу или возвращает на доработку с комментарием.
3. Видит своих студентов и их прогресс.

### Менеджер школы

1. Создаёт курсы, потоки (дата старта, часовой пояс, число мест, цена, ментор) и расписание: «по вторникам и четвергам в 19:00 по Киеву, 12 занятий».
2. Переносит отдельное занятие на другое время.
3. Создаёт промокоды: скидка, число использований, срок действия.
4. Видит студентов потока, лист ожидания, оплаты и возвраты. Переводит студента в другой поток или исключает его с возвратом.
5. Видит упавшие фоновые задачи и запускает их повторно.

### Администратор

1. Управляет сотрудниками и их ролями: менеджер, ментор.
2. Подключает платёжную систему: адрес, ключ.

## Правила

| Что | Правило |
| --- | --- |
| Места | по каждому потоку: оплаченные + удерживаемые + предложенные из листа ожидания ≤ число мест. Менеджер может увеличить число мест, но не уменьшить ниже уже занятых |
| Бронь места | 15 минут. Истёкшая бронь возвращает место ровно один раз. Оплата, пришедшая после истечения: если место ещё есть — студент записан, если нет — деньги возвращаются автоматически. Деньги без места не остаются никогда |
| Лист ожидания | очередь по времени записи. Освободившееся место предлагается первому в очереди на 24 часа; если он не оплатил, место переходит к следующему. Одно место — одно предложение |
| Цена | фиксируется в момент брони места. Промокод уменьшает цену; число использований промокода не превышает лимит даже при одновременных оплатах. Бронь, которая истекла или не оплачена, промокод не тратит |
| Перевод | в другой поток того же курса, если там есть место: новое место занимается и старое освобождается в одной транзакции. Разница в цене доплачивается или возвращается |
| Возврат | до старта потока — 100 %; до начала третьего занятия — 50 %; позже — без возврата. Время сравнивается по часовому поясу потока. Возврат по одной записи — не больше одного раза и не больше оплаченного |
| Расписание | занятия задаются по местному времени потока и не сдвигаются при переходе на летнее время. Студент видит их в своём часовом поясе |
| Напоминания | письмо за 24 часа и за 1 час до занятия, ровно одно каждого вида. После переноса занятия старые напоминания не приходят, новые — по новому времени |
| Домашка | дедлайн — 23:59 по часовому поясу потока через 7 дней после занятия. Работа, сданная после дедлайна, принимается с отметкой «поздно». У одной работы в любой момент не больше одного проверяющего |
| Сертификат | выдаётся после последнего занятия, если принято не меньше 80 % домашек. Номер сквозной по курсу, без пропусков и повторов. Выдаётся ровно один раз |
| Деньги | в минорных единицах валюты потока (UAH, EUR, USD). Оплаты и возвраты не удаляются и не меняются; баланс записи равен сумме её операций |

Статусы записи: `held`, `offered`, `paid`, `transferred`, `cancelled`, `refunded`, `expired`, `completed`. Статусы домашки: `submitted`, `in_review`, `accepted`, `returned`. Таблицы переходов (кто и из какого статуса) — в README.

**Журнал мест:** каждое изменение занятости потока (бронь, оплата, истечение, предложение из листа ожидания, перевод, отмена, исключение, изменение числа мест) — отдельная запись: поток, на сколько, по какой записи, кто, когда. Счётчики мест по каждому потоку всегда равны сумме журнала.

**Сид:**
- 200 курсов, 2 000 потоков в трёх часовых поясах (`Europe/Kyiv`, `Europe/Warsaw`, `America/New_York`) и трёх валютах, за 2 года и на полгода вперёд;
- 300 000 студентов, 500 000 записей, из них часть отменена, возвращена или переведена;
- 1 000 000 домашек в разных статусах, 100 000 сертификатов;
- несколько потоков, которые стартуют в ближайшие дни с последними свободными местами и листом ожидания;
- несколько потоков с занятиями на неделе перехода на летнее время.

Логины — в README.

## Заглушка платёжной системы

Отдельный сервис в `docker compose`:

- страница оплаты: кнопки «оплатить», «отказ», «закрыть без оплаты»;
- уведомляет сервис об оплате и возврате подписанным запросом (HMAC), повторяет при ошибке;
- принимает запросы на возврат, показывает все оплаты и возвраты;
- в режиме хаоса (переключатель в `.env`):
  - уведомление об оплате отправляется дважды, одновременно в обе копии `api`;
  - уведомление об оплате иногда приходит через 20 минут, когда бронь места уже истекла;
  - уведомление о возврате иногда приходит раньше ответа на запрос возврата;
  - каждый пятый запрос на возврат получает ответ 500 или таймаут.

## Инварианты

Это главное, что проверяется. Каждый инвариант должен держаться при одновременных запросах, повторах, рестарте процессов и потере Redis, и на каждый нужен тест.

1. **Мест не больше, чем есть.** Ни в одном потоке занятые места не превышают лимит; счётчики всегда равны сумме журнала.
2. **Последние места достаются честно.** 200 одновременных записей на 5 последних мест через обе копии `api` — ровно 5 броней, остальные получают «мест нет» и могут встать в лист ожидания.
3. **Бронь истекает один раз, деньги не теряются.** Оплата, пришедшая в момент истечения брони, — либо студент записан, либо место вернулось и деньги возвращены; никогда оба и никогда ни одного.
4. **Лист ожидания честный.** Освободились 3 места одновременно — предложения получили ровно трое первых, каждый одно. Непринятое предложение переходит к следующему один раз.
5. **Промокод не используется сверх лимита.** 50 одновременных оплат с промокодом на 10 использований — скидку получили ровно 10.
6. **Перевод атомарен.** Перевод в поток, где одновременно занимают последнее место, — либо студент в новом потоке и старое место свободно, либо остался в старом; никогда в обоих и никогда ни в одном.
7. **Оплата и возврат учитываются один раз.** Одно уведомление 10 раз в обе копии `api` — одна оплата. Возврат при ошибках платёжной системы доходит после повторов, вернули ровно один раз и не больше оплаченного. Отмена студентом и исключение менеджером одновременно — один возврат.
8. **Напоминания — ровно одно каждого вида и вовремя.** Включая неделю перехода на летнее время и перенос занятия за 30 минут до напоминания.
9. **Сертификаты без дублей и дыр.** При нескольких копиях `worker`, `kill -9` посреди выдачи и потере Redis каждый студент получил не больше одного сертификата, номера по курсу идут подряд.
10. **Фоновые задачи надёжны:**
    - `kill -9` воркера посреди истечения броней или выдачи сертификатов — после рестарта всё доделано без двойного учёта;
    - несколько копий `worker` не выполняют одну задачу дважды;
    - задача, исчерпавшая попытки, видна менеджеру и запускается повторно вручную.
11. **Потеря Redis ничего не ломает.** После `FLUSHALL` брони и предложения истекают, напоминания приходят, возвраты доходят, и ничего не выполняется дважды.
12. **Права — на сервере, в каждом эндпоинте и в сокетах:**
    - студент видит только свои записи, домашки и сертификаты;
    - ментор — только своих студентов и их работы;
    - менеджер — только свою школу;
    - ключ платёжной системы работает только для уведомлений;
    - сертификат проверяется по публичной ссылке, но ссылку нельзя подобрать;
    - на некорректный ввод — понятная ошибка с кодом, одинаковая по формату во всех эндпоинтах и описанная в OpenAPI; никогда «Internal server error».

Время в задачах (15 минут брони, 24 часа предложения, напоминания, дедлайны, границы возврата) подменяется в тестах.

## Что сдать

- Репозиторий: `apps/api`, `apps/worker`, `apps/web`, `packages/shared`.
- Запуск: `cp .env.example .env && docker compose up --build`.
  - `docker compose`: `postgres`, `redis`, `api` ×2, `nginx`, `worker`, `web`, заглушка платёжной системы, почтовый ящик для писем.
  - Миграции и сид создаются сами, других ручных шагов нет.
- Swagger на `/docs`; сгенерированный клиент совпадает со схемой — проверка в CI.
- Кабинет студента работает с телефона (ширина 375 px).
- Свободные места в каталоге, очередь ментора и список студентов потока у менеджера обновляются вживую; обратный отсчёт брони считается по часам сервера.
- Формы с ошибками у полей.
- Скорость: поиск в каталоге — быстрее 200 мс; очередь ментора — быстрее 200 мс; поиск студента по имени и email — быстрее 300 мс; отчёт за 12 месяцев — быстрее 1 с.
- Отчёт для менеджера: заполняемость потоков, выручка и возвраты, конверсия листа ожидания, доля сданных вовремя домашек, выданные сертификаты. Период и фильтры — в URL.
- e2e:
  - студент находит курс → бронь места → оплата → письмо → место в каталоге уменьшилось вживую;
  - мест нет → лист ожидания → другой студент отменил → предложение → оплата;
  - бронь истекла → оплата пришла поздно, места нет → автоматический возврат;
  - домашка → ментор вернул на доработку → пересдача → принята → после последнего занятия сертификат;
  - перевод в другой поток с доплатой; отмена после старта → возврат 50 %.
- README:
  - запуск и тесты;
  - как считаются места и почему нельзя продать лишнее, включая лист ожидания и перевод;
  - как защищены бронь, оплата, возврат и перевод от одновременных действий и повторов;
  - как считаются расписание, напоминания и дедлайны в часовых поясах, с примером на переходе на летнее время;
  - список фоновых задач: когда ставятся, повторы, защита от дублей, восстановление после потери Redis;
  - таблицы статусов записи и домашки;
  - индексы и ограничения в базе;
  - принятые решения.
